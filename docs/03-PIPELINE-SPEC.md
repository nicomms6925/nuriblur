# 03. 처리 파이프라인 스펙

## 한 줄 요약
분석 패스는 트랙 DB를 만들고, 렌더링 패스는 트랙 DB와 규칙만으로 출력한다. 설정을 바꿔도 분석은 다시 하지 않는다.

## 패스 1 — 분석 (Analyze)
| # | 단계 | 입력 → 출력 | 기본 파라미터 | 비고 |
|---|---|---|---|---|
| 1 | probe | 파일 → MediaInfo | — | VFR이면 `-vsync cfr`로 정규화 대상 표시, 회전 메타(90/180/270) 적용 |
| 2 | decode | 파일 → RGB 프레임 큐 | 링버퍼 64, HW 디코드 우선(NVDEC/QSV/D3D11VA) | HEVC 10-bit HW 미지원 시 SW 폴백 + warning 이벤트 |
| 3 | detect | 프레임 → 박스[cls, conf, xyxy] | 모델 YOLOX-s, 입력 1280(장변), conf 0.25(plate 0.25, face 0.30, person 0.35), NMS 0.5, 배치 8, **검출 간격 2프레임**(정적 카메라 4) | 사이 프레임은 추적기 예측. **(승인됨, 2026-10-02)** face conf 0.30 → **0.15** — 재검사(0.20)보다 낮춰 임계 부근 소형 얼굴에 여유(군중 실영상에서 0.2~0.3 얼굴 대량 노출) |
| 4 | track | 박스 시퀀스 → 트랙 | ByteTrack: high 0.5 / low 0.1, match 0.8, buffer 30프레임; 칼만 보간; 트랙 시작 전/종료 후 패딩 5프레임 | 클래스별 독립 추적. **(승인됨, 2026-10-01)** 연관되지 않은 모든 검출(클래스 임계 통과분)로 새 트랙을 만들고, 미확정 트랙은 검출 3회분 동안 유지·재연결 — 원본 기준(≥0.6)이면 0.3~0.6 얼굴이 마스킹되지 않음 |
| 5 | identify | 얼굴 트랙 → 임베딩 / 번호판 트랙 → 텍스트 | 얼굴: 선명도 상위 3프레임 ArcFace(112×112), 평균 벡터. 번호판: 상위 5프레임 OCR, 정규식 통과분 다수결 | V1. MVP는 OCR만 선택적 |
| 6 | link | 얼굴↔전신 트랙 연결 | 얼굴 박스가 전신 박스 상단 40% 안에 IoA ≥0.7 & 시간 겹침 ≥60% | 보호 승계용 |
| 7 | save | 트랙 → .nbproj | SQLite + 트랙별 썸네일(96px) | checkpoint_frame 갱신 |

성능 목표: RTX 4060 1080p 분석 ≥60 FPS (검출 간격 2 포함).

## 패스 2 — 렌더링 (Render)
1. `rules.apply()` → `track_decision` (deny-by-default). 신뢰도 낮은 보호 후보는 `REVIEW` 플래그 + 마스킹 유지.
2. 프레임별 마스킹 영역 생성: 박스 ×1.25 확장, 좌표 EMA α=0.6, 패딩 프레임 포함, 전신 마스킹 옵션 시 전신 박스.
   **(추가, 2026-10-02) 보호대상 외 전체 가리기**(`mask_all_unprotected`, 기본 끔): 비보호 사람은 전신 박스, 비보호 차량(번호판 선택 시 YOLOX 차량을 `vehicle` 트랙으로 저장)은 차체 박스 전체를 가린다. 번호판↔차량은 얼굴↔전신과 같은 방식으로 연결(번호판 박스가 차량 박스 안 IoA ≥0.7인 프레임이 60% 이상)해 보호를 양방향 승계한다. 보호된 차량 박스는 재검사 보호 영역에 넣지 않는다(운전자 얼굴 재검사 유지).
3. 마스킹 적용:
   | 스타일 | 파라미터 | 하한 |
   |---|---|---|
   | pixelate (기본) | block = w/8 | ≥ 8px |
   | gaussian | σ = w/4 | σ ≥ 15 |
   | solid | 검정 / 평균색 | — |
   | segment (V2) | SAM2 마스크 + feather 4px | — |
   번호판 크기 < 20px(장변)이면 차량 전체(전신에 해당하는 vehicle 박스 없음 → 번호판 박스 ×3)로 폴백.
4. 인코딩 **(변경, 2026-10-02: Media Foundation `h264_mf`/`hevc_mf`는 비트레이트 모드에서 복잡한 장면이 번지고 뭉개져 품질 모드 `quality` 55/65/45(원본/고화질/보통)로 인코딩 — 파일이 커질 수 있음. 키프레임 2초)**: 원본 코덱 유지, 비트레이트 = 원본 ×1.0(상한 원본 ×1.5), NVENC/QSV/VideoToolbox → 없으면 openh264/x264(LGPL 빌드 주의). `-c:a copy`, `-map_metadata -1`(메타 제거 기본 on), 타임스탬프 보존.
5. `audit_check` **(승인됨, 2026-10-01 — docs/11 §3)**: 출력본을 검출기(conf 0.2)로 재검사하되 두 가지를 본다.
   - 노출 검사(2패스 합의): (A) 출력 그대로, (B) 마스크 영역을 회색으로 덮은 출력에 각각 검출기를 돌려, B의 검출 중 A에도 같은 자리에 있는 것만 노출로 센다. 보호 트랙 박스(±패딩 프레임)와 IoU ≥0.3이거나 검출의 70% 이상이 보호 박스(×1.25) 안이면 제외. (출력 그대로만 보면 모자이크 자체가 얼굴로 다시 잡혀 끝나지 않는 루프가 생긴다)
   - 무결성 검사: 원본을 함께 디코딩해 마스크 영역이 실제로 바뀌었는지 확인(`mask_missing`), 출력 프레임 수 일치 확인.
   - **(승인됨, 2026-10-02)** 식별 불가 소형 얼굴: 폭 16px(원본 픽셀) 미만 얼굴은 노출로 세지 않는다. 분석·마스킹은 크기와 무관하게 그대로 하고, 제외 건수는 로그로 남긴다.
   - 1건이라도 있으면 실패 → 노출 프레임 목록 반환. 검수에서 노출 영역 마스킹 후 재렌더링.
   - **(승인됨, 2026-10-02) 오탐 확인**: 검수자가 재검사 항목을 '노출 아님'으로 확인(사유 필수)하면 통과로 인정한다.
     최근 재검사 결과의 얼굴·번호판 항목만, 신뢰도 0.5 미만만 가능(0.5 이상·`mask_missing`·프레임 수 불일치는 확인 불가 → 마스킹/재렌더링).
     확인 내역(프레임·위치·신뢰도·확인자·사유·출력본 해시)은 프로젝트에, 기관 모드는 감사 로그(`재검사 오탐 확인`)에도 남고,
     다시 렌더링해도 같은 프레임·같은 자리(IoU ≥0.5)의 같은 종류 검출은 세지 않는다. 남은 노출이 0이 되면 AUDITED.

## 제어
`Control(job, action)`: `pause | resume | cancel`. 분석 중단 시 처리된 트랙은 `checkpoint_frame`까지 보존, 재개 시 이어서.

## 트랙 병합 규칙 (ID 스위치)
- 자동 제안: 끊긴 구간 ≤ 2초, 임베딩 코사인 ≥ 0.5, 마지막/첫 박스 중심 거리 ≤ 박스 폭×2 → `merge_suggestion`
- 사용자가 승인하면 `track.merged_into` 설정, 보호 상태 승계.
